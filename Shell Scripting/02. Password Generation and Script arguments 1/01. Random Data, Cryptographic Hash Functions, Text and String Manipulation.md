# Generating Random Passwords in Bash

## Goal of This Lesson

In an earlier script, the user was asked to type a password while creating an account. That needs manual input every time.

In this lesson, we will learn different ways to generate random data using Bash. We will use this random data to build a script that creates strong passwords automatically. The more we can automate, the better.

---

## 1. The `$RANDOM` Built-in Variable

Bash has a built-in variable called `RANDOM`. Since it is written in all capital letters, we can guess it is a bash built-in (by convention, variables are written in capitals).

You can confirm this by checking the **VARIABLES** section of the bash man page.

**What it does:**
Each time `$RANDOM` is used, Bash generates a random integer between 0 and 32767.

### Example

```bash
echo $RANDOM
```

Output (will be different every time):

```
4308
```

Every time you run this command, you get a different number.

### Using `$RANDOM` in a Script

```bash
#!/bin/bash
# This script generates a list of random passwords

PASSWORD=$RANDOM
echo $PASSWORD
```

Run it like this:

```bash
chmod 755 luser-demo05.sh
./luser-demo05.sh
```

Each run prints a different random number.

> **Tip:** You can use `!v` (called an **event designator**) to quickly re-run the last command that started with `v`, such as `vim luser-demo05.sh`. Similarly, `!.` re-runs the last command starting with a dot (`./script.sh`).

### Making It Longer

A single `$RANDOM` value may be too short for a strong password. We can combine multiple `$RANDOM` values:

```bash
PASSWORD=$RANDOM$RANDOM$RANDOM
echo $PASSWORD
```

This gives a longer number, but the length still varies each time.

**Limitation:** Using only numbers is fine for a temporary password (one that the user must change at first login), but it is not very strong for a permanent password.

## 2. Using the `date` Command

Time is something that always changes — it is never the same again. This makes the current date and time a good source of "randomness" for generating passwords.

### Syntax

```bash
date [OPTION]... [+FORMAT]
```

- `date` — prints or sets the system date and time.
- `+FORMAT` — an optional format string (starts with `+`) that controls how the output looks.
- Format codes begin with `%`. For example:
  - `%a` — abbreviated weekday name
  - `%A` — full weekday name
  - `%s` — seconds since `1970-01-01 00:00:00 UTC` (called **Epoch time**, **Unix time**, or **POSIX time**)
  - `%N` — nanoseconds

### Example: Epoch Time

```bash
date +%s
```

Output:

```
1700000014
```

This number keeps increasing by 1 every second.

### Using Epoch Time as a Password

```bash
PASSWORD=$(date +%s)
echo $PASSWORD
```

Here, `$(command)` runs the command inside the parentheses and stores its output into the variable.

**Problem:** This is guessable.

- There are only 86,400 seconds in a day.
- If someone knows the password was generated during work hours (say, an 8-hour window), the guesses reduce to about 28,000–29,000 possibilities.

### Making It Harder to Guess: Add Nanoseconds

```bash
date +%s%N
```

Now the output has the seconds **plus** 9 digits of nanoseconds. This makes guessing much harder, because getting the exact nanosecond is nearly impossible.

```bash
PASSWORD=$(date +%s%N)
echo $PASSWORD
```

## 3. Checksums and Hash Functions

We can make passwords even more random-looking by converting our data into a **checksum** (also called a **cryptographic hash**).

### What Is a Checksum?

A checksum is a numeric value calculated from a block of data. It is used to verify that data (like a downloaded file) has not been changed or corrupted.

**How it is normally used:**

1. A website publishes the checksum of a file (for example, an ISO image).
2. You download the file and calculate its checksum yourself.
3. If your checksum matches the published one, the file is identical (not corrupted).

### Common Checksum Commands

```bash
sha1sum FILE
sha256sum FILE
md5sum FILE
```

### Example: Verifying a Downloaded File

```bash
sha1sum CentOS-7-Minimal.iso
```

Compare the output with the published `sha1sum` value. If the beginning and end of both values match, the file is the same.

```bash
sha256sum CentOS-7-Minimal.iso
```

### Even a Tiny Change Breaks the Checksum

If you add even a single character to a file:

```bash
echo a1 >> CentOS-7-Minimal.iso
```

...and calculate the `sha256sum` again, the checksum will be **completely different**. This shows how sensitive checksums are to any change in data.

### Other Hash Commands Available

```bash
ls -l /usr/bin/*sum*
```

This shows commands like `cksum`, `md5sum`, `sha1sum`, `sha224sum`, `sha256sum`, and more. They all do the same basic job: reduce a large block of data into one unique-looking string.

### Why Checksums Make Good Passwords

A `sha256sum` value is a **hexadecimal number** — it uses 16 possible characters (`0-9` and `A-F`) and is 64 characters long. That is a very strong password.

### Turning the Current Time into a Checksum

We can **pipe** (`|`) the output of `date` into `sha256sum`. A pipe takes the output of one command and feeds it as input to the next command.

```bash
date +%s | sha256sum
```

Output:

```
b7e23ec29af22b0b4e41da31e868d57226121c84dab8c7f2a1c2c0c6f5b6a5b -
```

**Why this works:** Commands like `sha256sum` accept either a file name, or — if no file is given — standard input. This is a common pattern in Linux commands.

```bash
sha256sum [OPTION]... [FILE]...
```

> With no FILE, or when FILE is `-`, it reads standard input.

## 4. Controlling Password Length with `head`

Once we generate a long checksum, we may want to trim it down to a specific size. The `head` command helps with this.

### Checking if `head` is Built-in or a Program

```bash
type -a head
```

Output shows `head` is located at `/usr/bin/head`, which means it is a program, not a shell built-in. So we must use `man head` instead of `help head` to read its documentation.

### Syntax

```bash
head [OPTION]... [FILE]...
```

Common options:

| Option | Meaning |
|---|---|
| `-c N` or `--bytes=N` | Print only the first N bytes (characters) |
| `-n N` or `--lines=N` | Print only the first N lines (default is 10 lines) |
| `-N` (old style) | Same as `-n N`, an older shorthand |

### Examples

```bash
head -n1 /etc/passwd     # first line
head -n 1 /etc/passwd    # same as above, with a space
head -1 /etc/passwd      # old-style shortcut, same result
head -2 /etc/passwd      # first two lines
head -c1 /etc/passwd     # first character only
head -c2 /etc/passwd     # first two characters
```

### Using `head` with Standard Input

```bash
echo testing | head -c2
```

Output:

```
te
```

### Chaining `date`, `sha256sum`, and `head` Together

You can chain multiple pipes, not just one. Each pipe passes data to the next command.

```bash
date +%s | sha256sum | head -c8
```

This takes the current time, hashes it, and keeps only the first 8 characters. Run it again to see a completely different result.

For even more randomness, use nanoseconds too:

```bash
date +%s%N | sha256sum | head -c8
```

### Adding This to the Script

```bash
#!/bin/bash
# This script generates a list of random passwords

PASSWORD=$(date +%s%N | sha256sum | head -c32)
echo $PASSWORD
```

This produces a 32-character password that looks completely random.

### Making It Even Stronger

We can mix in `$RANDOM` values along with the date, before hashing:

```bash
PASSWORD=$(date +%s%N$RANDOM$RANDOM | sha256sum | head -c48)
echo $PASSWORD
```

This generates a 48-character password with even more randomness.

> This method is good enough for most cases, especially if you plan to force a password change at first login. There are more advanced and secure ways to generate passwords, but this technique is simple and effective.

## 5. Adding a Random Special Character

To make the password even stronger, we can add one random special character to it.

### Step 1: Define the Special Characters

```bash
S='!@#$%^&*()_+-='
echo $S
```

### Step 2: Turn the String Into One Character Per Line — `fold`

The `shuf` command (explained next) works on whole **lines**, not individual characters. So first we need to break our string of special characters into separate lines using `fold`.

#### Syntax

```bash
fold [OPTION]... [FILE]...
```

| Option | Meaning |
|---|---|
| `-b` | Count width in bytes |
| `-c` | Count width in characters |
| `-w N` | Use width N instead of the default (80) |

To split every character onto its own line, use a width of 1.

```bash
echo $S | fold -w1
```

> **Note:** `-b1` and `-c1` also work, but they may add an extra blank line at the end. Using `-w1` avoids that issue, so it is the preferred option here.

### Step 3: Randomize the Order — `shuf`

#### Syntax

```bash
shuf [OPTION]... [FILE]
```

`shuf` writes a random permutation (random order) of the input lines to standard output.

#### Example

```bash
shuf /etc/passwd
```

Running this multiple times shows the lines of the file printed in a different, random order each time.

### Step 4: Combine `fold` and `shuf`

```bash
echo $S | fold -w1 | shuf
```

This prints the special characters in random order, one per line, and the order changes every time you run it.

### Step 5: Pick Just One Character

```bash
echo $S | fold -w1 | shuf | head -c1
```

This gives one random special character, such as `$`, `)`, `#`, or `^`.

### Final Script: Password + Special Character

```bash
#!/bin/bash
# This script generates a list of random passwords

SPECIAL_CHARACTER=$(echo '!@#$%^&*()_+-=' | fold -w1 | shuf | head -c1)
PASSWORD=$(date +%s%N$RANDOM$RANDOM | sha256sum | head -c48)

echo "${PASSWORD}${SPECIAL_CHARACTER}"
```

Each time you run this script, you get a strong, unique password that includes a random special character at the end.

## The Problem-Solving Pattern Used in This Lesson

This lesson followed a repeating pattern that is very useful in Linux/Unix work:

```
1. Know your goal
   (e.g., "I want one random special character")
        |
        v
2. Display what you currently have
   (e.g., echo the special characters)
        |
        v
3. Change the output using a pipe
   (send the output of one command into another command)
        |
        v
4. Repeat step 3 until the goal is reached
```

This works because of the **Unix philosophy**: each command should do only one job, and do it well.

- `echo` — only displays text, nothing else.
- `fold` — only rewraps text into lines.
- `shuf` — only randomizes line order.
- `head` — only trims output to a certain size.
- `sha256sum` — only calculates a hash.

By piping (`|`) these small, specialized commands together, we can build something new and useful — in this case, a strong random password generator.

---

## Anti-Patterns to Avoid

- **Don't** use only `$RANDOM` numbers for a permanent (non-expiring) password — it is weak and predictable.
- **Don't** use plain Epoch time (`date +%s`) alone as a password — it is guessable within a small range of numbers.
- **Don't** forget to check `type -a COMMAND` before assuming something is a shell built-in; using `help` on a program (instead of `man`) will not work.
- **Don't** rely on `-b1` or `-c1` with `fold` if you want clean one-character-per-line output — prefer `-w1`.

## Quick Reference Table

| Command | Purpose | Example |
|---|---|---|
| `$RANDOM` | Bash built-in variable, gives a random integer (0–32767) | `echo $RANDOM` |
| `date +%s` | Prints seconds since Epoch (Jan 1, 1970) | `date +%s` |
| `date +%s%N` | Prints seconds and nanoseconds (harder to guess) | `date +%s%N` |
| `sha1sum` / `sha256sum` | Calculates a checksum (hash) of data or a file | `sha256sum file.iso` |
| `head -c N` | Prints only the first N characters | `echo test \| head -c2` |
| `head -n N` | Prints only the first N lines | `head -n1 /etc/passwd` |
| `fold -w1` | Splits a line into one-character-per-line | `echo $S \| fold -w1` |
| `shuf` | Randomly shuffles the order of input lines | `shuf /etc/passwd` |
| `\|` (pipe) | Sends output of one command as input to the next | `date +%s \| sha256sum` |

## Practice Questions

**Q1: What does the `$RANDOM` bash variable return?**
A: A random integer between 0 and 32767, generated fresh each time it is referenced.

**Q2: What is "Epoch time"?**
A: The number of seconds that have passed since January 1, 1970, 00:00:00 UTC. It can be printed using `date +%s`.

**Q3: Why is `date +%s` alone not a strong password?**
A: Because there are only 86,400 possible values in a day, making it easy to guess, especially if the approximate time of generation is known.

**Q4: What does the `%N` format do in the `date` command?**
A: It prints the nanosecond value at the moment the command runs, adding a lot more unpredictability.

**Q5: What is a checksum used for?**
A: To verify that data (such as a downloaded file) has not changed or become corrupted, by comparing a calculated hash value to a published one.

**Q6: How can you use a checksum command on data that is not a file?**
A: By piping data into it using standard input, since commands like `sha256sum` read from standard input when no file is given.

**Q7: What is the difference between `head -c` and `head -n`?**
A: `-c` limits output by number of characters (bytes), while `-n` limits output by number of lines.

**Q8: Why is `fold -w1` used before `shuf` when picking a random special character?**
A: Because `shuf` randomizes whole lines, not individual characters. `fold -w1` breaks the string into one character per line so `shuf` can randomize character order.

**Q9: What does the `shuf` command do?**
A: It prints a random permutation (random order) of input lines to standard output.

**Q10: What is the Unix philosophy demonstrated in this lesson?**
A: Each command should do one job well. Complex results are achieved by piping together several small, specialized commands rather than using one big command.
