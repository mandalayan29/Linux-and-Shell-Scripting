## 4. Testing a Number (Only Show a Message if UID is Not 1000)

### Applying the DRY Principle

**DRY** stands for **"Don't Repeat Yourself."** Instead of typing the number `1000` in multiple places in your script, store it once in a variable. If you ever need to change that value later, you only change it in **one place**.

```bash
UID_TO_TEST_FOR=1000
```

```
Without DRY (bad):                With DRY (good):

if [[ "${UID}" -ne 1000 ]]         UID_TO_TEST_FOR=1000
then                               if [[ "${UID}" -ne "${UID_TO_TEST_FOR}" ]]
    echo "...1000..."              then
fi                                     echo "...${UID_TO_TEST_FOR}..."
... (repeated elsewhere) ...       fi
                                    ... (reuse the variable everywhere) ...
```

> In a small script, this may not seem important. But in longer, more complex scripts, using variables like this saves you a lot of trouble later.

### Writing the If Statement (Negative Test)

**Syntax:**
```
if [[ VALUE -ne VALUE_TO_COMPARE ]]
then
    commands
fi
```

**Example:**
```bash
UID_TO_TEST_FOR=1000

if [[ "${UID}" -ne "${UID_TO_TEST_FOR}" ]]
then
    echo "Your UID does not match ${UID_TO_TEST_FOR}"
    exit 1
fi
```

This reads as: *"If the UID is **not equal to** the UID we are testing for, then show a message and stop the script."*

## 5. The `exit` Command and Exit Status

### What is an Exit Status?

Every command and script returns a number called an **exit status** (also called exit code or exit value) when it finishes.

| Exit Status | Meaning (by convention) |
|---|---|
| `0` | Success |
| Any non-zero number (1, 2, 9, 99, 244...) | Some kind of failure or specific condition |

### The `exit` Shell Builtin

**Syntax:**
```
exit [N]
```

- `N` is optional (shown by the square brackets in the help text).
- If you don't provide `N`, the script exits using the status of the **last command that ran**.
- If you want to be clear and intentional, always specify the exit status yourself.

**Getting help:**
```
help exit
```

**Example:**
```bash
exit 1
```

### Real-World Example: `useradd` Exit Values

Checking the man page for `useradd`:

```
man useradd
/exit
```

The man page lists several exit values, for example:

| Exit Value | Meaning |
|---|---|
| `0` | Success |
| `2` | Invalid command syntax |
| `9` | Username already in use |

This is useful because your script can check the exact exit value and respond differently — for example, telling the user *"that username is already taken"* instead of a generic error.

### Reviewing Arithmetic Test Operators

**Syntax:**
```
help test
```

| Operator | Meaning |
|---|---|
| `-eq` | Equal to |
| `-ne` | Not equal to |
| `-lt` | Less than |
| `-le` | Less than or equal to |
| `-gt` | Greater than |
| `-ge` | Greater than or equal to |

We used `-ne` (not equal) in our script above.

### Testing the Script with Different UIDs

**Running normally (as `ayan`, UID 1000):**
```
./luser-demo03.sh
```
**Output:**
```
Your UID is 1000
```
No warning message appears, because `1000 -ne 1000` is **false**.

**Running as root using `sudo`:**

**Syntax:**
```
sudo <command>
```

**Example:**
```
sudo ./luser-demo03.sh
```
**Output:**
```
Your UID is 0
Your UID does not match 1000
```

Since root's UID is `0`, and `0 -ne 1000` is **true**, the warning message appears and the script exits with status `1`.

```
Logic Flow:

    UID = 0 (root)
        |
        v
   Is 0 -ne 1000 ? -----> YES (true)
        |
        v
   Print "does not match" + exit 1
```

## 6. Capturing Command Output and Checking If It Succeeded

### Capturing the Username

```bash
USER_NAME=$(id -un)
```

### The `$?` Special Variable

Bash automatically stores the **exit status of the most recently executed command** in a special variable called `$?` (or `${?}` with curly braces).

```
Command runs
     |
     v
Exit status saved automatically into $?
     |
     v
You can check $? right after with an if statement
```

**Example — checking if the `id` command succeeded:**
```bash
USER_NAME=$(id -un)

if [[ "${?}" -ne 0 ]]
then
    echo "The id command did not execute successfully"
    exit 1
fi

echo "Your username is ${USER_NAME}"
```

### How This Works

- `id -un` runs and its output is stored in `USER_NAME`.
- `$?` now holds the exit status of that `id -un` command.
- If `$?` is **not equal to 0**, something went wrong, so we print an error and exit.
- If we get past the `if` block, that means `id -un` worked fine, so we go ahead and display the username.

### Demonstrating `$?` on the Command Line

**Example (successful command):**
```
id -un
echo $?
```
**Output:**
```
ayan
0
```

**Example (a command that fails on purpose):**
```
id -x
echo $?
```
**Output:**
```
id: invalid option -- 'x'
1
```

This shows that a failed command returns a **non-zero** exit status (in this case, `1`).

> **Convention:** When testing for success, check `if $? -ne 0` (not equal to zero), since `0` always means success.

## 7. Testing Strings

So far we tested **numbers**. Now let's test a **string** (text) value, like a username.

### Testing for Equality (String)

```bash
USER_NAME_TO_TEST_FOR='ayan'

if [[ "${USER_NAME}" = "${USER_NAME_TO_TEST_FOR}" ]]
then
    echo "Your username matches ${USER_NAME_TO_TEST_FOR}"
fi
```

### Single `=` vs Double `==`

The `=` sign has two different meanings depending on **where** it's used:

| Location | Meaning |
|---|---|
| `USER_NAME_TO_TEST_FOR='ayan'` | **Assignment** — storing a value into a variable |
| `[[ "${USER_NAME}" = "${USER_NAME_TO_TEST_FOR}" ]]` | **Test/comparison** — checking if two values are equal |

You may also see a **double equal sign** (`==`) used inside `[[ ]]`:

```bash
if [[ "${USER_NAME}" == "${USER_NAME_TO_TEST_FOR}" ]]
```

- `==` treats the right-hand side as a **pattern** for pattern matching.
- `=` performs a plain, exact match.

Since we just want an exact match (no pattern matching), a single `=` is enough. Some people use `==` out of habit even for exact matches — both work for simple equality checks, so you'll see either in real scripts.

### Running the Script

**As `ayan` (normal user):**
```
Your UID is 1000
Your username is ayan
Your username matches ayan
```

**With `sudo` (as root):**
```
Your UID is 0
Your UID does not match 1000
```
The script exits early at status `1` (from the earlier UID check), so it never reaches the username test.

**Checking the exit status after running with `sudo`:**
```
echo $?
```
**Output:**
```
1
```
This confirms the script exited with the status we set (`exit 1`) when the UID check failed.

## 8. Testing for "Not Equal" (String)

**Syntax:**
```
if [[ "STRING1" != "STRING2" ]]
then
    commands
fi
```

**Example:**
```bash
if [[ "${USER_NAME}" != "${USER_NAME_TO_TEST_FOR}" ]]
then
    echo "Your username does not match ${USER_NAME_TO_TEST_FOR}"
    exit 1
fi
```

This reads as: *"If the username is **not equal to** the username we are testing for, show a message and stop the script."*

## 9. Setting the Final Exit Status

At the very end of the script, if everything succeeded, it's good practice to be **explicit** about the exit status:

```bash
exit 0
```

### Why Be Explicit?

If you don't specify an exit status:
- The `exit` command (or the script itself) will use the exit status of the **last command that ran before it**.
- Sometimes that's what you want — but often it's safer to be clear and set it yourself.

**Convention:**
```
exit 0   → Script completed successfully
exit 1+  → Script failed (choose a number that makes sense for your script)
```

### Running the Final Script and Checking the Result

```
./luser-demo03.sh
echo $?
```

**Output:**
```
Your UID is 1000
Your username is ayan
Your username matches ayan
0
```

The final `0` confirms our script completed successfully, exactly as intended.

## 10. Full Script Example

```bash
#!/bin/bash
# This script displays the UID and username of the user
# running it, and checks both against expected values.

# 1. Display the UID
echo "Your UID is ${UID}"

# 2. Only display a message if UID does not match 1000
UID_TO_TEST_FOR=1000
if [[ "${UID}" -ne "${UID_TO_TEST_FOR}" ]]
then
    echo "Your UID does not match ${UID_TO_TEST_FOR}"
    exit 1
fi

# 3. Display the username
USER_NAME=$(id -un)

# 4. Test if the id command succeeded
if [[ "${?}" -ne 0 ]]
then
    echo "The id command did not execute successfully"
    exit 1
fi
echo "Your username is ${USER_NAME}"

# 5. Test the string for equality
USER_NAME_TO_TEST_FOR='ayan'
if [[ "${USER_NAME}" = "${USER_NAME_TO_TEST_FOR}" ]]
then
    echo "Your username matches ${USER_NAME_TO_TEST_FOR}"
fi

# 6. Test the string for inequality
if [[ "${USER_NAME}" != "${USER_NAME_TO_TEST_FOR}" ]]
then
    echo "Your username does not match ${USER_NAME_TO_TEST_FOR}"
    exit 1
fi

exit 0
```

## Summary

In this tutorial, you learned:

- How to write a **negative `if` test** (checking if something is **not** equal, using `-ne` for numbers and `!=` for strings).
- The **DRY principle** — store repeated values in a variable instead of typing them multiple times.
- The `exit` command lets you **stop a script early** and set a specific **exit status**.
- **Exit status convention:** `0` means success, any non-zero number means some kind of failure.
- The special variable `$?` (or `${?}`) always holds the **exit status of the last command that ran** — use it right after a command to check if it succeeded.
- **String comparisons** use `=` (or `==`) for equality and `!=` for inequality, inside `[[ ]]`.
- `=` is a plain exact match; `==` treats the right side as a pattern (though both work fine for simple exact matches).
- Always be **explicit** about your script's final exit status using `exit 0` (success) or `exit N` (failure) at the end.

### Quick Command Reference

| Command / Syntax | Purpose |
|---|---|
| `exit [N]` | Stop script execution with an optional exit status |
| `$?` or `${?}` | Holds the exit status of the last executed command |
| `[[ VALUE -ne VALUE2 ]]` | Numeric "not equal" test |
| `[[ "STR1" = "STR2" ]]` | String equality test |
| `[[ "STR1" != "STR2" ]]` | String inequality test |
| `help exit` | Get help on the exit builtin |
| `help test` | Get help on test operators |
| `man useradd` | View exit status meanings for the useradd command |
| `sudo <command>` | Run a command as the root user |
