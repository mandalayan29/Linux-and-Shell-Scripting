## Introduction

In this tutorial, you will learn:

## 3. Why We Need User Input

So far, our scripts have run completely on their own, with no interaction needed. But sometimes a script needs information **from the person running it** to do its job — like a username and password for a new account.

### Two Ways to Get Input

1. **The `read` shell builtin** — asks the user to type something while the script is running. *(This is what we'll use in this lesson.)*
2. **Command-line arguments** — the user supplies information when they first launch the script (covered in a later lesson).

---

## 4. The `read` Shell Builtin

### Checking That `read` is a Builtin

**Syntax:**
```
type read
type -a read
```

Running `type read` shows that it's a shell builtin. Running `type -a read` shows **all** versions available — the shell builtin (which runs by default) and possibly an external file like `/usr/bin/read` (which won't be used unless you specify its full path).

### Getting Help

**Syntax:**
```
help read
```

Since the help output is long, pipe it through a pager:
```
help read | less
```

**What the description says:**
> Read a line from the standard input and split it into fields.

### About Standard Input, Output, and Error

There are three default types of input/output in Linux:

| Type | Default Source/Destination |
|---|---|
| **Standard Input (stdin)** | The keyboard |
| **Standard Output (stdout)** | The screen |
| **Standard Error (stderr)** | The screen |

> **Note:** Standard input doesn't *always* have to come from the keyboard — it can also come from another command, as you'll see later in this tutorial with pipes.

### How `read` Handles Multiple Words

The `help read` output explains that the input line gets split into "fields," and any leftover words are assigned to the **last** variable name given. If you list several variable names after `read`, each word typed gets assigned to a separate variable. If you only give **one** variable name, the **entire line** (including spaces) gets stored in that single variable — which is exactly what we want for this script.

### The `-p` (Prompt) Option

**Syntax:**
```
read -p "prompt text" VARIABLE_NAME
```

The `-p` option lets you display a message asking the user for input, right before they start typing.

**Example:**
```
read -p "Type something: " THING
```

> **Tip:** Add a space at the end of your prompt string, so the user's typed text doesn't appear jammed right up against your prompt.

Try it out:
```
read -p "Type something: " THING
Type something: Fred
echo "${THING}"
```
**Output:**
```
Fred
```

Whatever the user types gets stored in the variable (`THING` in this example).

```
Flow of the read command:

   Script displays prompt ("Type something: ")
             |
             v
   User types text on keyboard + presses Enter
             |
             v
   Text is stored in the variable you specified
```

- `PASSWORD` will store the password to assign.

## 6. The `useradd` Command

### Syntax

```
useradd [OPTIONS] LOGIN
```

Checking the man page:
```
man useradd
```

- Anything in square brackets `[ ]` is **optional**.
- `LOGIN` (the username) is **required** — it's not inside brackets.

### Login vs Username

"Login" and "username" mean the same thing. The man pages use the word "login," but in everyday conversation and in this tutorial, we'll mostly say "username."

---

## 7. Username Rules and Conventions

### The Eight-Character Convention

By convention (not a strict rule), usernames are typically **8 characters or shorter**. This comes from historical limits in old Unix systems, which Linux inherited many of its conventions from. Because of this history, some commands (like `ps`) only display the first 8 characters of a username by default.

### Seeing the Effect of Long Usernames

**Example — creating a long username:**
```
sudo useradd dougstamper
```

**Switching to that user:**

**Syntax:**
```
su - USERNAME
```
or
```
su -l USERNAME
```

> The `-` (or `-l`) option tells `su` to start a fresh **login shell environment**, similar to what you'd get logging in normally.

**Example:**
```
su - dougstamper
```
Since we're running this as root (via `sudo` earlier), no password is required.

**Checking the process table:**
```
ps -ef
```

In the output, you'll notice the username column shows only the first 8 characters (`dougstam`) followed by a `+` sign, indicating the name was cut off. This doesn't break anything — it's just a display quirk in older commands like `ps` due to the historical 8-character limit.

```
Username: dougstamper (11 characters)
ps -ef shows:  dougstam+
                └───┬───┘└┘
              first 8 chars  "+" means truncated
```

Exit back to your normal account when done:
```
exit
```

### Other Username Rules

- **Usernames are case-sensitive.** `doug` and `Doug` are two different accounts. By convention, always use **lowercase**.
- **No special characters** are allowed (like `@`, `#`, `!`).
- **Numbers are allowed.** For example, if multiple employees share the last name "Smith," you could create `smith1`, `smith2`, `smith99`, and so on.

## 8. Useful `useradd` Options

### `-c` (Comment)

**Syntax:**
```
-c "COMMENT"
```

Adds a short description to the account — historically used for the person's real name.

**Example:**
```
-c "Jane Smith"
```

**Other common uses for the comment field:**
- The application that uses the account (if it's not a person's account).
- The person's name **plus** a help-desk ticket number, for auditing purposes. This way you can trace exactly who requested the account, who approved it, and who created it.

### `-m` / `--create-home`

**Syntax (short form):**
```
-m
```
**Syntax (long form):**
```
--create-home
```

Both do the **exact same thing** — you only need to use one. The short form is quicker to type; the long form is more readable/explicit. This tutorial uses the short form, `-m`.

**What it does:**
- Creates the user's home directory if it doesn't already exist.
- Copies files from a "skeleton" directory (`/etc/skel` by default) into the new home directory. You can change this default location with the `-k` option.

### Where Does the Default Behavior Come From?

If you don't use `-m`, whether a home directory gets created depends on a setting called `CREATE_HOME` inside a configuration file.

**Checking the configuration file:**
```
cat /etc/login.defs
```

Look for a line like:
```
CREATE_HOME     yes
```

> **Important:** This default setting can be **different on different systems**. If you want to be 100% sure a home directory always gets created, don't rely on this file — just explicitly use the `-m` flag in your script. This makes your script more predictable and portable.

### Putting It Together

**Example command used in the script:**
```bash
useradd -c "${COMMENT}" -m "${USER_NAME}"
```

### Why the Comment is in Quotes

The `COMMENT` variable might contain **spaces** (like "Jane Smith"). Wrapping it in quotes makes Bash treat it as **one single value**, instead of splitting it into separate words/arguments.

```
Without quotes:                  With quotes:
-c Jane Smith                    -c "Jane Smith"
   |                                 |
   treated as TWO arguments         treated as ONE argument
   ("Jane" and "Smith")             ("Jane Smith")
```

## 9. Setting the Password with `passwd`

### The Problem: `passwd` Normally Asks Interactively

**Syntax:**
```
passwd [USERNAME]
```

By default, running `passwd` prompts you to type a new password interactively:
```
passwd
```
This works fine when a human is typing directly, but it's not useful inside an automated script — we need a way to supply the password **without** manual typing.

### Understanding Pipes and Standard Input

Recall that standard input can come from something other than the keyboard — specifically, from **another command**, using a **pipe** (`|`).

```
Pipe (|) behavior:

   Command A  --->  standard output  --->  |  --->  standard input  --->  Command B
```

- The pipe takes the **standard output** of the command on the left and feeds it in as the **standard input** of the command on the right.
- **Note:** Standard *error* messages from the first command are **not** passed through the pipe — only standard output is.

### The `--stdin` Option

Checking the man page:
```
man passwd
```

The `--stdin` option tells `passwd` to read the new password from **standard input** instead of prompting interactively — which means it can accept input piped in from another command.

**Syntax:**
```
echo "PASSWORD" | passwd --stdin USERNAME
```

**Example (used in the script):**
```bash
echo "${PASSWORD}" | passwd --stdin "${USER_NAME}"
```

### How This Works

```
echo "${PASSWORD}"
        |
        | (pipe sends this text as standard input)
        v
passwd --stdin "${USER_NAME}"
        |
        v
Password is set for USER_NAME, without any manual typing
```

---

## 10. Forcing a Password Change on First Login

### The `-e` Option (Expire)

**Syntax:**
```
passwd -e USERNAME
```

This immediately **expires** the account's password, which forces the user to set a new password the next time they log in. This is a good security practice — the administrator sets a temporary password, and the real user picks their own private password on first login.

**Example (used in the script):**
```bash
passwd -e "${USER_NAME}"
```

## 11. Full Script Example

```bash
#!/bin/bash
# This script creates a user account on the local system.
# It asks the person running it for a username, real name, and password.

# 1. Ask for the username
read -p "Enter the username: " USER_NAME

# 2. Ask for the real name of the person
read -p "Enter the full name: " COMMENT

# 3. Ask for the password
read -p "Enter the password: " PASSWORD

# 4. Create the user
useradd -c "${COMMENT}" -m "${USER_NAME}"

# 5. Set the password for the user
echo "${PASSWORD}" | passwd --stdin "${USER_NAME}"

# 6. Force the user to change their password on first login
passwd -e "${USER_NAME}"
```

```
Enter the username: jsmith

Enter the password: jsmith123
```

**Output:**
```

```

### Testing the New Account

**Syntax:**
```
su - USERNAME
```

**Example:**
```
su - jsmith
```

Since we're logged in as a **normal user** (not root), the system will ask for `jsmith`'s **password** (root can switch to any account without a password, but a regular user cannot).

```
Password: jsmith123
```

Because we used `passwd -e` earlier, the system immediately forces a password change:
```
You are required to change your password immediately.
New password:
Retype new password:
```

After successfully setting a new password, you'll be logged in as `jsmith`.

To return to your normal account:
```
exit
```

## Summary

In this tutorial, you learned:

- The **`read`** shell builtin captures a line of keyboard input and stores it in a variable. Use `-p "prompt text"` to display a message before the user types.
- There are three standard input/output types: **standard input** (keyboard, by default), **standard output**, and **standard error** (both go to the screen, by default).
- The **`useradd`** command creates new accounts. `LOGIN` (the username) is required; everything else is optional.
- Usernames are conventionally **8 characters or fewer, lowercase, no special characters** (though numbers are fine).
- `useradd -c "COMMENT"` adds a description (commonly a real name or ticket number) to the account.
- `useradd -m` (or `--create-home`) guarantees the home directory gets created, regardless of the system's default `CREATE_HOME` setting in `/etc/login.defs`.
- **Pipes (`|`)** send the standard output of one command into the standard input of the next command.
- `echo "password" | passwd --stdin USERNAME` sets a password **without** an interactive prompt — useful for automation.
- `passwd -e USERNAME` **expires** a password immediately, forcing the user to set a new one on their next login.

### Quick Command Reference

| Command / Syntax | Purpose |
|---|---|
| `read -p "text" VAR` | Prompt the user and store their input in a variable |
| `useradd -c "comment" -m username` | Create a new user with a description and home directory |
| `echo "pass" \| passwd --stdin username` | Set a password without an interactive prompt |
| `passwd -e username` | Force a password change on next login |
| `su - username` | Switch to another user with a full login environment |
| `chmod +x <file>` or `chmod 755 <file>` | Make a script executable |
| `cat /etc/login.defs` | View default account creation settings |
