# Arithmetic in Bash, and Handling Remaining Arguments With `OPTIND`

## Goal of This Lesson

In this lesson, we will learn how to perform math in Bash using **arithmetic expansion**, explore alternative tools (`bc`, `awk`, `let`, `expr`), and then return to `getopts` to learn how to correctly handle any extra command-line arguments left over after processing options, using the `OPTIND` variable.

---

## 1. Arithmetic Expansion: `$(( ))`

### Syntax

```bash
VARIABLE=$(( EXPRESSION ))
```

This is called **arithmetic expansion**. Bash evaluates the expression inside the double parentheses and substitutes the result in its place.

### Basic Operators

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `+` | Addition | `$((1 + 2))` | `3` |
| `-` | Subtraction | `$((10 - 1))` | `9` |
| `*` | Multiplication | `$((2 * 4))` | `8` |
| `/` | Division | `$((6 / 4))` | `1` |
| `%` | Modulo (remainder) | `$((6 % 4))` | `2` |

### Examples

```bash
NUM=$((1 + 2))
echo $NUM
```

```
3
```

```bash
NUM=$((10 - 1))
echo $NUM
```

```
9
```

```bash
NUM=$((2 * 4))
echo $NUM
```

```
8
```

### Division: An Important Limitation

```bash
NUM=$((6 / 4))
echo $NUM
```

```
1
```

Mathematically, `6 / 4` is `1.5` — but Bash returns `1`.

> **Key point:** Bash does **not** round numbers and does **not** support floating-point (decimal) arithmetic. It simply drops everything after the decimal point. This is usually fine, since most scripting math involves simple whole-number operations — adding values, counting loop iterations, and so on.

---

## 2. Doing Floating-Point Math: `bc`

When you truly need decimal precision, you need an external program, such as `bc` ("basic calculator").

### Checking If `bc` Is Installed

```bash
type -a bc
```

If it's not found, install it:

```bash
sudo yum install -y bc
```

### Syntax

```bash
bc [OPTION]...
```

| Option | Meaning |
|---|---|
| `-l` | Load the math library, enabling floating-point (decimal) math |
| `-h` | Show help |

`bc` reads from **standard input**, so it's commonly used with a pipe.

### Example: Floating-Point Division

```bash
echo "6 / 4" | bc -l
```

```
1.50000000000000000000
```

### Using `bc` as an Interactive Calculator

```bash
bc -l
```

At the prompt, type expressions:

```
6 / 4
1.50000000000000000000
1 + 1
2
```

Press `Ctrl+D` to exit the calculator.

---

## 3. Doing Floating-Point Math: `awk`

`awk` can also perform floating-point math, though it is a bit more cumbersome for this purpose. It's shown here mainly so you can recognize this pattern if you see it in someone else's script.

### Example

```bash
awk 'BEGIN { print 6 / 4 }'
```

```
1.5
```

Whether you use `bc` or `awk`, you get the full, precise answer — unlike Bash's built-in arithmetic expansion, which truncates decimals.

---

## 4. The Modulo Operator (`%`)

Back to Bash's built-in arithmetic. The `%` operator returns the **remainder** of a division.

```bash
NUM=$((6 % 4))
echo $NUM
```

```
2
```

`6 / 4` is `1`, with a remainder of `2` — that remainder is what `%` returns.

### Practical Use: Detecting Even and Odd Numbers

- An **even** number divided by 2 always has a remainder of `0`.
- An **odd** number divided by 2 always has a remainder of `1`.

```bash
if (( NUM % 2 == 0 )); then
  echo "even"
else
  echo "odd"
fi
```

This kind of check is useful for alternating behavior in a script, and pairs naturally with an `if` or `case` statement.

---

## 5. Using Variables Inside Arithmetic Expansion

You are not limited to hardcoded numbers — variables work too.

```bash
DICEA=3
DICEB=6
TOTAL=$((DICEA + DICEB))
echo $TOTAL
```

```
9
```

> **Important:** Inside the double parentheses `$(( ))`, you do **not** use a leading `$` before variable names. Just write `DICEA`, not `$DICEA`. This is different from how you normally reference variables elsewhere in Bash.

---

## 6. Changing a Variable's Value Directly

You can modify a variable's value in place, still without a leading `$`, since we're not substituting a value — we're changing the variable itself.

### Increment (`++`) and Decrement (`--`)

```bash
NUM=1
((NUM++))
echo $NUM
```

```
2
```

```bash
((NUM--))
echo $NUM
```

```
1
```

### Compound Assignment Operators

| Operator | Meaning | Example (starting `NUM=1`) | Result |
|---|---|---|---|
| `+=` | Add and assign | `((NUM += 5))` | `6` |
| `-=` | Subtract and assign | `((NUM -= 5))` | `-4` |
| `*=` | Multiply and assign | `((NUM *= 5))` | `5` |
| `/=` | Divide and assign | `((NUM /= 5))` | `0` |
| `%=` | Modulo and assign | `((NUM %= 5))` | `1` |

```bash
NUM=1
((NUM += 5))
echo $NUM
```

```
6
```

### Alternative: Using Substitution Syntax

If the plain `((...))` form feels less clear, you can achieve the same result using the familiar `$(( ))` substitution syntax:

```bash
NUM=$((NUM += 5))
echo $NUM
```

```
11
```

(Continuing from `NUM=6`, `6 + 5 = 11`.) This takes the output of the arithmetic operation and explicitly assigns it back to `NUM`. Both styles are valid — use whichever reads more clearly to you.

## 7. Two More Ways to Do Math: `let` and `expr`

You may encounter these in other people's scripts, so it's good to recognize them, even if the `$(( ))` syntax is generally recommended.

### The `let` Built-in

```bash
help let | less
```

The help output lists all supported operators — post-increment (`++`), pre-increment, `+=`, `-=`, and so on — the same set used with `$(( ))`.

#### Syntax

```bash
let EXPRESSION
```

#### Examples

```bash
let NUM=2+3
echo $NUM
```

```
5
```

```bash
let NUM++
echo $NUM
```

```
6
```

`let` behaves essentially the same as double-parentheses arithmetic — it's simply an alternate syntax.

### The `expr` Command

`expr` is an **external command** (not a Bash built-in), unlike the double-parentheses syntax, which is built directly into Bash. It processes an expression and prints the result to standard output.

#### Syntax

```bash
expr EXPRESSION
```

#### Example

```bash
expr 1 + 1
```

```
2
```

#### Assigning the Result to a Variable

Use standard command substitution, just like with any other command:

```bash
NUM=$(expr 2 + 3)
echo $NUM
```

```
5
```

> **Recommendation:** Prefer the built-in `$(( ))` syntax whenever possible, since it doesn't require launching an external program like `expr` or `bc` (unless you specifically need floating-point math).

## 8. Back to `getopts`: Handling Leftover Arguments

`getopts` processes options like `-v`, `-l`, `-s` — but it does **not** automatically remove them from the script's positional parameters. This means `${@}`, `${1}`, `${2}`, and so on **still contain the original, unprocessed arguments**, even after `getopts` has finished reading the options.

### Demonstrating the Problem

Add some debug output after the `getopts` while loop:

```bash
echo "Number of arguments: ${#}"
echo "All arguments: ${@}"
echo "First argument: ${1}"
echo "Second argument: ${2}"
```

Run the script:

```bash
./luser-demo11.sh -sl 8 extra-stuff
```

Output:

```
Number of arguments: 3
All arguments: -sl 8 extra-stuff
First argument: -sl
Second argument: 8
```

Even though `-sl 8` were already processed as options by `getopts`, they are **still sitting in the positional parameters** — `${1}` is `-sl`, `${2}` is `8`, and `${3}` would be `extra-stuff`.

**The problem:** Ideally, once options are processed, they should be removed, leaving only the genuinely "extra" arguments (like `extra-stuff`) behind. `getopts` doesn't do this automatically — but it gives us the information needed to do it ourselves.

---

## 9. The `OPTIND` Variable

`getopts` automatically sets a variable called **`OPTIND`**, which stores the position (index) of the **next** argument that comes after all the processed options.

### Demonstration

```bash
./luser-demo11.sh -sl 8 extra-stuff
echo "OPTIND is: ${OPTIND}"
```

```
OPTIND is: 3
```

Since `-sl 8` occupies positions `1` and `2`, the next unprocessed argument (`extra-stuff`) starts at position `3` — exactly what `OPTIND` reports.

### The Formula: `OPTIND - 1`

To remove exactly the options that were already processed, shift the positional parameters by `OPTIND - 1`.

```bash
shift $((OPTIND - 1))
```

### Verifying the Formula With Different Inputs

**Example 1: One option only**

```bash
./luser-demo11.sh -s extra-stuff
echo "OPTIND is: ${OPTIND}"
```

```
OPTIND is: 2
```

`OPTIND - 1` = `2 - 1` = `1`. Shifting by `1` removes exactly the one option (`-s`), leaving `extra-stuff` as the new `${1}`.

**Example 2: No options at all**

```bash
./luser-demo11.sh extra-stuff
echo "OPTIND is: ${OPTIND}"
```

```
OPTIND is: 1
```

`OPTIND - 1` = `1 - 1` = `0`. Shifting by `0` changes nothing — which is exactly correct, since there were no options to remove.

```mermaid
flowchart LR
    A["getopts processes -s -l 8 ..."] --> B["OPTIND = position of next unprocessed argument"]
    B --> C["shift $((OPTIND - 1))"]
    C --> D["Remaining $@ contains only leftover arguments"]
```

### Adding the Shift to the Script

```bash
while getopts vl:s OPTION; do
  case "${OPTION}" in
    v) VERBOSE=true ;;
    l) LENGTH="${OPTARG}" ;;
    s) SPECIAL=true ;;
    ?) usage ;;
  esac
done

shift $((OPTIND - 1))
```

Now `${@}`, `${1}`, `${2}`, and so on refer only to whatever is left **after** all the options.

### Verifying the Result

```bash
echo "After the shift:"
echo "Number of arguments: ${#}"
echo "All arguments: ${@}"
echo "First argument: ${1}"
```

```bash
./luser-demo11.sh -sl 8 extra-stuff
```

Output:

```
After the shift:
Number of arguments: 1
All arguments: extra-stuff
First argument: extra-stuff
```

The only thing left is `extra-stuff` — exactly what we want.

## 10. Handling Extra Arguments: Two Approaches

Once options are cleanly separated from remaining arguments, you have options for how to handle what's left:

### Option A: Expect and Use Remaining Arguments

If your script requires something after the options (like a filename or username), you can loop through `${@}` or directly test `${1}`, `${2}`, and so on to process them.

### Option B: Treat Any Leftover Arguments as an Error

For this script, we want **only** options — nothing else should be supplied. The simplest way to enforce this is to check `${#}` after the shift.

```bash
if [[ "${#}" -gt 0 ]]; then
  usage
fi
```

**Why this works:** Since `shift` changes the positional parameters, it also updates `${#}` — so after removing all processed options, `${#}` correctly reflects only the count of any genuinely extra, unexpected arguments.

We reuse the `usage` function here too, since it both teaches the user correct usage and exits with a non-zero status.

## 11. Final Testing

### Extra Argument With No Options

```bash
./luser-demo11.sh extra-argument
```

Output shows the usage message, because there's one leftover argument after the shift, and `usage` is triggered.

### Valid Option Plus Extra Argument

```bash
./luser-demo11.sh -s extra-stuff
```

Even though `-s` was a valid, correctly processed option, `extra-stuff` remains after the shift, so `${#} -gt 0` is still true, and `usage` runs again.

### Correct Usage

```bash
./luser-demo11.sh -s
```

Output:

```
Your password is: 9f3e6b7d...#
```

No leftover arguments, so the script completes normally and prints the password with a special character appended.

## Anti-Patterns to Avoid

- **Don't** assume `getopts` automatically removes processed options from `${@}` — it doesn't. You must `shift` them away yourself using `OPTIND`.
- **Don't** use a leading `$` on variable names inside `$(( ))` or `(( ))` — write `NUM`, not `$NUM`, inside arithmetic expressions.
- **Don't** rely on Bash's built-in arithmetic for anything requiring decimal precision — use `bc -l` or `awk` instead.
- **Don't** forget that `expr` is an external program, while `$(( ))` is a Bash built-in — prefer the built-in for portability and performance when floating-point math isn't needed.
- **Don't** forget that `shift` changes `${#}` too — this is exactly what makes checking `${#} -gt 0` after a `shift` a reliable way to detect leftover, unexpected arguments.

## Quick Reference Table

| Syntax | Purpose |
|---|---|
| `$(( EXPRESSION ))` | Arithmetic expansion — evaluates and returns the result of an integer expression |
| `+`, `-`, `*`, `/`, `%` | Add, subtract, multiply, divide, modulo (remainder) |
| `((NUM++))` / `((NUM--))` | Increment / decrement a variable by 1 |
| `((NUM += 5))` | Compound assignment (also `-=`, `*=`, `/=`, `%=`) |
| `bc -l` | External calculator supporting floating-point math; reads from standard input |
| `awk 'BEGIN { print EXPR }'` | Alternate way to compute floating-point math |
| `let EXPRESSION` | Bash built-in, alternate syntax for arithmetic (same operators as `$(( ))`) |
| `expr EXPRESSION` | External program that evaluates an expression and prints the result |
| `${OPTARG}` | Value assigned to an option that requires an argument (set by `getopts`) |
| `${OPTIND}` | Position of the next unprocessed argument, after all options (set by `getopts`) |
| `shift $((OPTIND - 1))` | Removes already-processed options from the positional parameters |

## Practice Questions

**Q1: What does `$(( ))` do in Bash?**
A: It performs arithmetic expansion — Bash evaluates the integer expression inside and substitutes the result.

**Q2: Why does `$((6 / 4))` return `1` instead of `1.5`?**
A: Because Bash's built-in arithmetic does not support floating-point numbers; it truncates (drops) anything after the decimal point rather than rounding.

**Q3: How can you perform floating-point division in a shell script?**
A: Use an external tool like `bc -l` (e.g., `echo "6 / 4" | bc -l`) or `awk` (e.g., `awk 'BEGIN { print 6 / 4 }'`).

**Q4: What does the modulo operator (`%`) return?**
A: The remainder of a division. For example, `6 % 4` returns `2`, since 6 divided by 4 is 1 with a remainder of 2.

**Q5: Do you use a leading `$` before a variable name inside `$(( ))`?**
A: No. Inside arithmetic expansion or `((...))`, variable names are written without the leading `$` (e.g., `NUM + 1`, not `$NUM + 1`).

**Q6: What is the difference between `let` and `expr`?**
A: `let` is a Bash built-in that uses the same arithmetic syntax as `$(( ))`. `expr` is a separate external program that evaluates an expression and prints the result to standard output.

**Q7: Does `getopts` automatically remove processed options from the positional parameters?**
A: No. The options remain in `${@}`, `${1}`, `${2}`, etc. even after `getopts` processes them — you must manually `shift` them away.

**Q8: What does the `OPTIND` variable represent?**
A: The position (index) of the next command-line argument that comes right after all the options that `getopts` has processed.

**Q9: What is the correct formula for shifting away already-processed options after using `getopts`?**
A: `shift $((OPTIND - 1))`.

**Q10: After using `shift $((OPTIND - 1))`, how can you detect if the user supplied any unexpected extra arguments?**
A: Check `${#}` — since `shift` updates the count of remaining positional parameters, any value greater than `0` indicates leftover, unexpected arguments.
